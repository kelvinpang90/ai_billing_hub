# ADR-0016 — 供应商价格：V1 不做自动同步适配器，只用手工录入草稿

| | |
| --- | --- |
| **状态** | **已接受**：决策人 2026-11-14 拍板 |
| **日期** | 2026-11-14 |
| **来源** | spec §18、§131；AIH-TASK-026（设计闸门 #177 v3）的供应商价格版本 |
| **影响** | Phase 8 的「供应商价格同步适配器」不实现；`provider_price_versions.source_type` 的 `SYNC` 取值保留不用 |
| **相关** | Invariant 6 |

---

## 背景

spec §131 的 Phase 8 清单列了「供应商价格同步适配器」，spec §18 要求架构支持「自动发现或同步 → 草稿 → 管理员审批 → 发布」，并规定没有完全自动的取价途径时支持手工录入。

现状：

- 草稿 → 审批 → 发布与历史版本已由 AIH-TASK-026 交付：价格版本 `DRAFT → PUBLISHED → RETIRED`（草稿可 `DISCARDED`），记录 `approved_by` / `approved_at`，发布后由 MySQL 触发器保证不可改。`source_type` 预留了 `SYNC`，现在只有 `MANUAL`。
- 平台目前接的供应商（Anthropic；spec 提到 OpenAI 转写）都没有官方的价格查询 API。所谓同步只能抓官网价格页，页面结构一改就坏，抓错的价格还要靠人审批时发现。

## 决策

1. V1 不实现供应商价格同步适配器，也不抓取任何官网页面。价格一律由管理员按草稿手工录入，照常审批、发布。这正是 spec §18 给出的退路（没有完全自动的取价途径时支持手工录入）。
2. `source_type` 的 `SYNC` 取值和数据库 CHECK 保持原样，不删：将来某个供应商提供官方价格 API 时，适配器只写草稿，审批与发布流程不变。
3. Phase 8 其余三项（供应商账单成本对账、Reprocess、Rebill 调整）不受本 ADR 影响，仍按 `docs/TODO.md` 待登记。

## 备选方案

- **抓官网价格页写草稿**：格式无契约，随时可能坏；坏了以后要么不报错地不再出草稿，要么写出错的草稿。省下的只是管理员手工录入几行价格的时间，而价格变动本身一年也没几次。不采用。
- **等供应商出官方 API 再做**：就是本决策。到那时另写 ADR，按第 2 条接上。

## 后果

- 负面：供应商调价后，平台要等管理员看到并录入草稿才会跟上。这段时间里按旧价格估算成本，毛利报表会偏离。spec §14 的对账后成本（Phase 8 账单对账）是纠正这种偏离的途径。
- 负面：没有「供应商调价了」的自动提醒，只能靠管理员自己关注供应商公告。
- 正面：没有脆弱的抓取代码，也没有需要维护的外部依赖。所有生效价格都经过人工录入与审批，每次改价都留有版本记录。

## 收口条件

- 某个已接入的供应商提供官方、可鉴权的价格查询 API 时，重新评估，另写 ADR。
- 管理员因漏录调价造成实际损失时，重新评估提醒机制（例如定期提示复核价格）。

## 背景

spec v1.0 的 §36 与 §37 自相矛盾：§36 说「secret 只存安全哈希」，§37 又要求 HMAC 请求签名。**HMAC 验签需要服务端持有密钥材料，只存哈希根本验不了签。**这是 [SPEC_REVIEW_v1.0.md](../SPEC_REVIEW_v1.0.md) 的 P0-2，评审判定「这条不改，实现方一定会做错」。

v1.1 已修正。§36 现在明确：

> 请求签名密钥与出站 Webhook 签名密钥必须使用**认证式可逆加密**或有文档的安全密钥派生方案，因为 HMAC 需要密钥材料。**口令式单向哈希对这些密钥无效。**

## 已定的原则（spec，不在本 ADR 的决策范围内）

| 项 | 要求 | 出处 |
| --- | --- | --- |
| API Key | 非机密标识符，可按查找形式存储 | §36 |
| 签名 Secret | 认证式可逆加密存储 | §36、§74.4 |
| 主密钥位置 | **存在数据库之外**，通过生产密钥管理注入 | §36 |
| 主密钥备份 | 独立访问控制，单独备份，纳入恢复流程 | §36、§98.1 |
| 泄露面 | 日志、审计前后值、API 响应、异常栈**都不得**出现明文 | §36、§94 |
| 轮换 | 支持有界重叠期 + 显式 `key_version`；过期后旧版本停止验签 | §36 |
| 展示 | 创建后**永不**再次返回明文 | §36、§74.4 |
| 撤销 | 每个 API key 可独立撤销 | §36 |

`integration_credentials` 已有 `encrypted_secret` 与 `key_version` 字段（§74.4），`projects` 有 `encrypted_webhook_secret` 与 `webhook_key_version`（§76）。**表结构不因本 ADR 的选型而变。**

## 待决策：用什么实现

约束前提：V1 是**单 VPS + Docker Compose**（§99），**没有云基础设施依赖**。这排除了一部分常见答案。

### 选项 A — 应用层信封加密，主密钥来自宿主机密钥管理 ⭐ 推荐

```text
明文 secret
  → AES-256-GCM 加密（数据密钥）
  → 数据密钥用主密钥加密后与密文同存
主密钥 → 宿主机文件（严格 chmod）或 systemd credential / Docker secret，
         经环境注入，绝不入库、绝不入镜像、绝不入仓库
```

- ✅ 无外部依赖，与单 VPS 架构一致
- ✅ AEAD 提供完整性，密文被篡改会解密失败而不是产出垃圾密钥
- ✅ 轮换只需换数据密钥并递增 `key_version`，主密钥轮换单独走一次重加密
- ✅ Python 生态成熟（`cryptography` 库）
- ❌ 主密钥的保管与恢复全靠自建流程，做错了就是全盘泄露
- ❌ 主密钥丢失 = 所有 secret 不可恢复，必须全部轮换（§98.1 要求把主密钥恢复写进 runbook）

### 选项 B — 外部 KMS（云厂商）

- ✅ 主密钥永不离开 KMS，审计与轮换是托管的
- ❌ **与 §99 的单 VPS 无云依赖冲突**，引入外网调用与账单
- ❌ KMS 不可达时验签全挂 —— 会变成 AI 请求路径外的又一个可用性依赖
- ❌ V1 阶段为一个尚无客户的系统引入云绑定，不划算

### 选项 C — SOPS / age 之类的文件级加密

- ✅ 适合加密**配置文件**
- ❌ 不适合**运行时逐条解密数据库里的 secret**，每次验签都要调外部进程
- ❌ 轮换粒度太粗

## 需要一并拍板的三个细节

即使选了 A，下面三条仍要明确，否则实现方会各写各的：

1. **主密钥怎么注入** —— 宿主机文件 + Docker secret？还是 systemd credential？备份放哪、谁有权限拿？
2. **主密钥轮换流程** —— 重加密全表的停机窗口、失败回滚、验证方式
3. **重放保护存储**（[TODO.md](../TODO.md) 的 R4）—— §37 只说「别把 Redis 硬编码成唯一重放存储」，nonce 的存储介质与 TTL（应等于签名时间窗大小）未定。这条和密钥方案一起定比较省事

## 后果（按选项 A 预估）

### 正面

- 无外部依赖，`REQ-AVAIL-001` 不新增故障点
- 与 §98.1 的备份/恢复方案能统一设计

### 负面

- **主密钥的保管完全是自建流程**，没有托管服务兜底。流程写不清楚，就是最大的单点风险
- 恢复演练（§98.1 的季度演练）必须包含「主密钥恢复」这一项，否则备份等于没有
- 仓库是公开的（[ADR-0001](ADR-0001-repository-visibility.md)），密钥管理相关的主机路径、文件名等细节**不得写进仓库**，只能写在 runbook 的受控位置

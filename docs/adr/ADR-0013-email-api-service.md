## 背景

ADR-0009 定 Email 走自管 SMTP（传输层借 `rs-roof-pms`），并在备选方案 A 里记下了已知缺口：**SMTP 直连没有退信（bounce）与投诉处理，也拿不到投递事件**。硬退信会被持续投递，长期损害发送域名的信誉；发出去是否真的到达，只能靠客户反馈。

ADR-0009 当时说这个缺口「Phase 6 之前需要一个抑制列表方案，本 ADR 不定」。后来 TODO 把它提前到 Phase 4 之前重新评估，因为 Phase 4 起就有收据、支付确认这类**必须送达**的邮件。

可选的只有两条：

- **A. 继续 SMTP，自己补抑制列表**：要自己解析退信邮件（DSN）或接收件方反馈环路，各家格式不一，投诉信号基本拿不到
- **B. 改用 API 服务**：退信与投诉事件以 webhook 回调，服务端自带抑制列表

## 决策

### 1. Email 走 API 服务，不再用自管 SMTP（决策人 2026-10-15）

ADR-0009 第 2 节「Email 传输层借 `rs-roof-pms`」由本 ADR 取代；随之失效的还有 ADR-0009 的两处旧结论：备选方案 A「Email 用 API 服务 —— 未选」（现已选定），以及收口条件里「Email 与投递模型部分已可进入实现，无阻塞条件」（Email 的真实服务商实现现在受本 ADR「收口条件」约束，Adapter 接口、Outbox 与测试替身不受限）。ADR-0009 其余部分（Adapter 抽象、Outbox 投递模型、只在状态跃迁时发通知、WhatsApp）**不变**。

ADR-0009 第 2 节「不借」那张表的结论继续有效：不在请求内同步发送、必须有重试与发送记录、要有模板层、调用方必须知道发没发出去。这些与传输层选 SMTP 还是 API 无关。

「空配置 = 未配置、开发与 CI 不需要真实凭据」这条也继续有效，改由 Adapter 的测试替身承担。

### 2. 服务商准入条件（先定契约，后选供应商）

任何候选服务商必须**全部**满足：

| # | 条件 | 为什么 |
| --- | --- | --- |
| **E1** | 退信（硬 / 软分开）与投诉事件以 webhook 回调，且回调**可验签** | 这是换掉 SMTP 的全部理由；回调不验签，任何人都能伪造「退信」把客户邮箱打进抑制列表 |
| **E2** | 服务端抑制列表：硬退信与投诉自动抑制，且可通过 API 查询与移除 | 自己维护一份与服务端不一致的抑制列表，比没有更糟 |
| **E3** | 发送时可附带我方自定义标识，并在回调里原样带回 | 回调要能对回到具体的 Outbox 行，才能把投递状态落库（Invariant 14 要求能审计「这封信最后怎样了」） |
| **E4** | 支持自有发送域名的 SPF / DKIM 验证 | 不用服务商共享域名发计费邮件 |
| **E5** | 有测试模式或沙箱，能在不发真实邮件的情况下触发退信与投诉事件 | E1–E3 必须实测，不能凭文档；`REQ-LAUNCH-001` 还要求上线前用真实账号验证 |

### 3. Adapter 边界不变

业务代码仍只依赖 Notification Adapter（ADR-0009 第 1 节）。换服务商只换 Email Adapter 的一个实现，Outbox 表结构不随服务商变化。

投递事件回调是新增的入站端点，按 Webhook 处理：验签、按服务商事件标识去重、先落库再处理。它涉及 Webhook，实现时按 [CLAUDE.md](../../CLAUDE.md) 的分档走设计闸门。

## 备选方案

### A. 继续 SMTP，自己补抑制列表 —— 未选

要自己收退信邮件并解析 DSN，格式因收件方而异；投诉（标为垃圾邮件）信号在 SMTP 侧基本拿不到。做出来的东西比 B 弱，维护成本却更高。

## 与 spec 的关系

spec §47 写的是「Reuse existing Acuven Email sending service」。Acuven 现有的 Email 资产是 SMTP（ADR-0009 背景），所以本 ADR **偏离了这句的字面**：决策人选择新增一家服务商，换取退信与投诉处理。spec §47 的其余要求（三个通道、Notification Adapter 抽象、`REQ-LAUNCH-001` 真实账号验证）不受影响。spec 措辞的同步留给后续，见 [TODO.md](../TODO.md)「后续计划」。

## 后果

### 正面

- 退信与投诉自动抑制，发送域名信誉有保护
- 每封信的投递结果可落库、可审计，不再「发出去就不知道了」

### 负面 —— 已知代价

- 多一家外部服务商：要选型、开账号、按量付费
- 多一个入站回调端点，要验签、去重、走设计闸门
- 服务商不可用时邮件发不出去；由 Outbox 重试兜底，与 SMTP 服务器不可用时一样
